# Leaf inventory color and shape CPU observations

Two fresh JVMs execute unchanged `bk.b(I)I` and inherited `uu.g()V` on the
original constructed `uu.L` singleton. All 16 metadata values and a separate
authored non-cube shape agree exactly. The client JAR SHA256 is
`af1fa04b8006d3ef78c7e24f8de4aa56f439a74d7f314827529062d5bab6db4c`.

`observations.txt` stores 17 raw LF rows: metadata, returned color bits and six
actual bound bits, followed by the authored shape after `g()`. `source-pins.json`
records class/Code hashes and complete BK/NR/JH declared-method inventories.
BK and NR have no `g()V`; UU's pinned body contains only return0. No original
class bytes or assets are stored. `provenance.json` binds the rows, source
identities, helper, capture script, observation JDK and compiled helper classes.
Both original runs report zero source network/native-link attempts and the
actual initialized JH array length 65,536.

BK tests metadata mask1 first at4 and invokes JH.a at7; only its false branch
tests mask2 at15 and invokes JH.b at18. Otherwise it invokes JH.c at22. Their
constant results are 6,396,257, 8,431,445 and 4,764,952. Each invocation performs
JH active use before entering the body, although none reads the array or uses
floating arithmetic. Metadata3 therefore selects Pine. These are inventory
colors; the World-climate overload has a different source body.

The native adapter uses its actual graphics namespace for JH and leaves the
Registry-only Leaf color boundary explicit. The native controls cover all 16
metadata values, signed metadata, cold JH initialization, a NULL ready array,
failed initializer propagation at the reached BK invocation, strict CV floating
admission and inherited shape preservation on live and RAW owners. CPU Display
calls fail at their real boundary; these controls do not fabricate GL success.

Run the native comparison against `mc_test_inventory_block`:

```text
python -B tests/reference/client/leaf_inventory/run_native.py --executable <native-test> --work-dir <artifacts>
```

The runner validates hashes/schema, compares all17 emitted rows and fingerprints
its selected inputs before/after. Reproduce the original captures locally:

```text
python -B tests/reference/client/leaf_inventory/capture_reference.py --jar <b1.7.3.jar> --libraries <minecraft-libraries> --output <new-directory>
```

This finite CPU evidence does not establish original CV/BB/GL rendering, pixels,
native allocation-failure equivalence, server behavior, saved gameplay or FPS.
The separate real SDK scene qualifies the reached native Item rendering path.
