# Recenter and JO sorting

The finite capture contains 12 unchanged whole `n.b(III)V` calls and 19 cases
using unchanged `jo` construction/comparison with JDK 17 object sorting. The
JO cohort uses an authored forwarding Comparator solely to record each actual
JO result or exception. It is not a whole `n.a(Lls;ID)I` observation. No game
method is changed, subclassed, instrumented or replaced.

Prepared RAW N/DK/camera identities and every coordinate, array and dirty List
are declared by `fixtures.py`. Recenter cases prepare the actual DK origins so
position calls return normally before GL; null/short arrays, null DKs and a
wrapped zero grid width retain the reached N bounds. These cases qualify the
whole recenter traversal and failure fields, including rectangular grids and
integer extremes. They do not claim moving-DK or constructor execution.

JO rows contain captured negated camera bits, final or partial identity order,
and every comparison/result. They cover ties, sub-integer comparison results,
signed zero, NaN, infinity, integer extremes, long TimSort input and null entries
after earlier insertion/merge work. Constructor failure remains separate from
a null array passed to sorting. The native replay uses the production JO leaf,
the shared JDK17 sort kernel and the actual entered N sort adapter; it compares
every field/trace row and checks the adapter retains the same final array.

The source pins bind the original JAR, complete selected classes and method
Code. The bounded capture uses JDK17, denies network, native links and writes,
checks loaded game classes come from that JAR, and fingerprints all inputs and
helper classes before and after. Public replay needs no JAR or JVM.

A separate device test uses the real saved-World fixture and canonical owners.
It completes a 200-DK rebuild with actual IN class use, recentering and JO sort;
moves clean DKs through their real bounds display lists and checks X/Z/Y queue
append order; then a null pass array in the third moving DK retains the first
two moves and appends. Native retirement releases all World leases. These are
native integration controls, not additional unchanged-original differential
rows or a terrain-frame/pixel comparison. Device testing follows the existing
`MC_ENABLE_CLIENT_DISPLAY_TESTS` profile; the 31-row CPU replay runs separately.
