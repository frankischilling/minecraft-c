# Original MovementInput comparison

`compare.py` invokes unchanged methods from the user's verified Beta 1.7.3
client JAR and compares them with the production C input owner. The reference
JAR SHA-256 is
`af1fa04b8006d3ef78c7e24f8de4aa56f439a74d7f314827529062d5bab6db4c`.
No original classfile or decompiled implementation is included here.

`provenance.json` pins the complete classfiles and method Code byte arrays for
`uo`, `lr`, `kv` and `qb`. The input closure is:

| Original method | C operation |
| --- | --- |
| `uo.<init>()V` | `mc_movement_input_create` |
| `lr.<init>(Lkv;)V` | `mc_movement_input_create_from_options` |
| `uo/lr.a(IZ)V` | `mc_movement_input_key` |
| `uo/lr.a()V` | `mc_movement_input_reset` |
| `uo/lr.a(Lgs;)V` | `mc_movement_input_update` |

The Java helper constructs actual original default GameSettings and
KeyBinding objects. It calls the real input methods and reads their fields;
reflection only inspects the private key array/settings identity and assigns
public named KeyBinding references. It does not replace a game class or
construct a Player. Both update bodies leave the supplied null Player unread.

The runner verifies JAR/class/Code hashes before launching the probe. It
clears ambient Java option variables, uses `-Xverify:all`, retains class-init
logs and rejects any initialized original class outside `uo/lr/kv/qb`.
Original Minecraft/World/Player/native graphics/audio initialization does not
belong to this closure.

## Authored inputs and projection

`inputs.json` supplies 77 finite scenarios and 857 ordered commands. It covers
all 64 six-key combinations, opposed/diagonal movement, jump/sneak, base no-ops,
float-bit field writes, null settings, each null named binding, all-six
duplicate codes, named aliases/replacements, NULL `w`, live code changes and
signed int32 extremes. Inputs are independent of observed output.

Every command emits one record containing source success/NPE, class kind,
strafe/forward raw float bits, `c/d/e`, settings presence, array length and
the ten-cell mask. That is ten projected fields per record; the ordinal binds
record order. Each observer also asserts that its array identity and stored
settings identity remain the actual constructor references.

Comparison is exact after splitting platform newline endings. No numeric
tolerance or expected-value substitution is used. Original NPEs compare with
the native source-exception category; native tests separately check exact
failure PCs and named indexes. Native argument/allocation/retirement policies
are not JVM heap or exception-allocation equivalence claims.

## Run

Build `tests/client/input/movement_input_probe.c` with the production
`movement_input.c` and GameSettings dependency. Then run with JDK 17 or the
validated local JDK and Python 3.10+:

```text
python tests/reference/client/input/compare.py --jar /path/to/b1.7.3.jar --native /path/to/movement_input_probe --work-dir /path/to/ignored/reference-output
```

`--java` and `--javac` select explicit JDK tools. The runner creates a fresh
run directory without deleting earlier results. It retains the exact plan,
original/native output, compiler output, class-init log and result hashes.
The C17 native probe consumes only the bounded authored plan generated by this
runner; it is not a general input parser.

`validation.json` records the finite local comparison and source pins. The
checks cover these two input classes; they do not establish native platform
keyboard translation, mouse behavior or a playable client.
