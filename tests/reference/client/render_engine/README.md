# Real RenderEngine constructor and texture ownership

This source-only package executes unchanged original ji/ge on explicit JDK17.
It qualifies a concrete C constructor/default-font owner and the selected actual
ID-generation, upload and image-map operation. It does not implement normal
Minecraft bootstrap, actual ik/selected texture packs, String/ImageIO lookup,
dynamic HTTP textures, effect registration/update, or the full px/ra/iy owner.

The actual ji(ik,kv) constructor creates four HashMaps, one ArrayList, direct
IntBuffer1 backed by its distinct four-byte direct buffer, direct ByteBuffer1MiB,
and TYPE_INT_ARGB64x64. It stores nullable pack/settings before Graphics creation,
fills white, draws black missingtex at(1,10) with the actual default Dialog12,
and disposes Graphics. There is no GL call in that constructor. Native classes
represent distinct ji/ge states; ge initializes its two real Lists only at the
first buffer call. Namespace, object, collection, buffer and image identities
and retained failed prefixes are inspectable. Native allocation quotas are
separate from Java OOME timing and do not claim all AWT failure implementations.

Production uses no JAR, Java process, captured glyph pixels, atlas or bundled
system font. The actual native provider discovers registered Arial through GDI
on the selected OpenJDK Windows Dialog alphabetic profile; Linux performs a real
Fontconfig sans match. It reads real font bytes and rasterizes with pinned
FreeType. The default monochrome/interpreter35 policy matches the observed JDK;
the same interpreter environment override is honored. Other logical-font/script
fallback chains are not implemented as successful substitutes. Native discovery
failures stop at draw150 with all prior image/Graphics effects retained.
[OpenJDK FontScaler](https://raw.githubusercontent.com/openjdk/jdk17u/master/src/java.desktop/share/classes/sun/font/FontScaler.java)
and its [FreeType scaler](https://raw.githubusercontent.com/openjdk/jdk17u/master/src/java.desktop/share/native/libfontmanager/freetypeScaler.c)
provide the primary rasterizer-policy reference. Exact results are measured
against the supplied unchanged binary and current real system font, not inferred
from those sources. Font metrics compared are all ten glyph IDs, origins,
advances and pixel bounds; ascent/descent/leading are observed JDK metadata.

Source ji.a(BufferedImage)I clears e, generates actual GL IDs and appends ge.b,
uploads, then retains the same original image in d. Nullable image fails only
at upload getWidth154, after real generation/binding/parameters. Nullable settings
explicitly skips anaglyph at261/264. CPU original-image storage and device storage
remain distinct: later image edits do not silently update uploaded texels.

The Display increment provides separate generated-resource, bind, parameter,
existing-ID upload and explicit retirement operations. Generated IDs survive
subsequent failures. Native bookkeeping precedes GL, owns each pending resource
and holds its actual Display context. Display destruction is BUSY until those
resources retire. Busy/current failures preserve retryable owners; context-loss
cleanup reports the loss and leaves driver retirement to context destruction.
No unbind/restore or delete-on-error convenience path changes source prefixes.
Legacy GL_CLAMP stops at its first unsupported core-context parameter; four-level
mipmap processing stops after level0 at its first unimplemented body460. These
frontiers are not successful original completions. The old convenience uploader
keeps its existing behavior.

```

```

Repeat with Python-O: all checks remain active. The controller requires actual
exit0/empty stderr and positive complete inventories. Mutations reject crashes,
sanitizer diagnostics, wrong prefix/cache/cursor rows and incomplete output;
argc failures require exact exit2 and diagnostic. Native tests use genuine
owners and actual contexts/readback, not fake GL tables or callbacks. The
optional actual GL debug callback exercises BUSY retirement during an operation.
