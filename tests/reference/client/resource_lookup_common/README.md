# Resource observations

The Java helpers construct the actual kq client, Settings, selected Pack and
RenderEngine from the supplied classes. Native probes use the real application
constructor and services. They retain whole arrays, cache/static identities,
source banners and native diagnostics. There are no captured answer tables,
replacement game classes or ready-child substitutes.

Color runs on the CPU without a Display. Texture separately owns a real Display
and records raw texture IDs and GPU bytes. IDs are never renumbered. GPU/provider
or context differences remain visible. Readback restores texture and pixel-pack
state. Native frontiers remain unfinished calls, with later stateful rows kept
as continuations when a whole original call cannot be paired.

The native producer snapshots were qualified on Windows MSVC Debug and Linux
Clang/GCC sanitized Debug: six selected tests and eleven native-only profiles.
This is a selected local scope, not the complete test suite. The later Python
reader and metadata changes are a separate admission policy; they were not
compiled into those executables. Producer source, direct executable, closed
product receipt and admission-policy identities must stay distinct.

One retained Windows JDK17 CPU default attempt has complete read-only origin,
capture, helper, input, source and product admission. Its seven rows match:
water, cache, grass, foliage, missing, clamp and blur. Other original profiles,
including ZIP, private getRGB helpers, cold statics and texture/GL, retain their
own pending scope. No full startup, World entry or gameplay result follows.

Profiles are finite: color default/zip, priority, frontiers, helpers, statics and
first-setter; texture default/zip, priority and frontiers. Cold claims require
actual class initialization inside the same captured stderr interval as the
flushed use markers. Warm prefixes are retained and refused as cold proof.
NULL/short getRGB cases preserve actual exceptions and partial destinations;
unfinished native cases stay explicit.

Original admission requires supplied game/SDK/JDK authorities with exact hashes.
The selected external nest metadata combines the unchanged nineteen old rows
with six byte-proved additions. Actual lib/modules class bytes equal pinned
java.base/java.desktop JMOD entries, including complete class/Code and reciprocal
nest attributes. The merged full metadata and classfiles remain private inputs;
this package publishes only the expected metadata identity. Generated JDK names
need exact earlier declaring/source events and classfile nest proof. There is no
name, prefix or generic jrt fallback. The original profile retains its Windows
JDK17 backing; it is not a qualified Linux original profile.

JDK unified logging accepts the exact library tag or exactly three trailing ASCII
spaces. Malformed padding and real diagnostics still reject ordinary profiles.
The public normal/-O controls use authored parser strings and require no JDK,
JAR, private logs or game resources. Absolute native loads keep their exact path
and byte checks. A VM-only name stays a name and supplies no inferred file origin.

Native controllers require a direct EXE/ELF and an externally qualified artifact
map, checked before and after the call. Complete configured artifact enumeration
belongs to the separately bound qualification receipt. Supply its exact map
SHA-256 or a closed product gate outside the enumerated build products.
Operational --native-stdout also requires --native-run-receipt and an independently
retained --native-run-receipt-sha256. It authenticates the accepted closed REPORT
before reading its records, then binds the original streams, complete capture,
command, producer source/mode/profile, input trees, executable and products.
Same-length substitutions and retied data with the old anchor reject. A new hash
of untrusted replay data cannot establish trust. Read-only consistency replay of
an existing complete REPORT remains separate and starts no game process.

Input preparation uses authored File/ZIP/PNG data plus required resources from
the user's verified supplied JAR. Original classes, assets, logs, JARs, full JDK
metadata and private worlds are not public payload. Native archive origin and
entry bytes are checked separately from actual JVM library load paths. No archive
origin is inferred merely from a filename or DLL hash.

Process capture keeps stdout, stderr, source prefixes and completion receipts
under fixed 180-second/8-MiB pipe bounds. Nonzero/77 exit, reader failure, timeout,
overflow, unknown origin or platform refusal is not success. No clock, entropy or
source-banner equality is required across runtimes. Native stop/join/retirement
is separate cleanup and does not manufacture Java source-finally effects.
