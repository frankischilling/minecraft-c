## Fresh reproduction

Use JDK17, Python3.10+, the supplied unchanged client JAR and the four pinned
LWJGL2.9.0/LWJGL-util/JInput/JUtils archives from a local installation. Linux also
needs Xvfb/xauth and the pinned LWJGL Linux native archive. The target generates
its authored images locally; no asset download occurs.

```sh
python3 -B tests/reference/client/living_overlay/capture.py --client-jar /path/b1.7.3.jar --sdk-library /path/lwjgl-2.9.0.jar --sdk-library /path/lwjgl_util-2.9.0.jar --sdk-library /path/jinput-2.0.5.jar --sdk-library /path/jutils-1.0.0.jar --native-archive /path/lwjgl-platform-2.9.0-natives-linux.jar --jdk /usr/lib/jvm/java-17-openjdk-amd64 --output .local/overlay-fresh
```

The output directory must be new. Full capture runs ordinary and read-only JDI
VMs with explicit time limits and retains failed attempts. For a separate
ordinary supplement, use `--ordinary-only --primary EXISTING_PRIMARY_CAPTURE`
and the matching platform's native archive. That mode reuses the primary's
compiled helper bytes. Run Windows graphical observations with exclusive access
to that desktop.

A fresh output is not automatically admitted as the pinned historical dataset.
Its receipt, helpers, class origins, complete outputs and current-file audit need
separate review and new provenance. This preserves the distinction between
reproduction, observation and qualification.
