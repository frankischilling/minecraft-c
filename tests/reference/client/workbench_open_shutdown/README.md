# Live-open Workbench native shutdown

The four Windows SDK profiles open the real Workbench, leave Logs in its grid,
Planks on the cursor and a real recipe result visible, then close the actual
source window. The native shutdown path transfers the same live IT owner to the
Player's terminal record. It preserves source screen, Container and Stack
identities while completing checked C cleanup.

`native-validation.json` records the fresh formatted-source cohort after
held-tool mining/destruction, Leaves/Snow-layer/Ice harvest and QM Leaf
World-color integration. The test helper waits for actual serial input
consumption during Table opening. Four tests pass in 62.22 seconds, with
1,843 / 2,014 / 2,239 / 2,281 native checks. Their measured CTest times are
15.33 / 16.01 / 15.78 / 15.07 seconds in clean / Container / Player / World order.
The Container profile
refuses before transfer; the Player and World profiles refuse at the later World
audit. Each releases only its declared existing hold and retries. All four end
with both source windows absent. The selected save tree stays byte-for-byte
equal to its stopped snapshot through every native phase.

The receipt binds all 1,438 runtime source files and 487 selected harness/CMake
files. Each process recorded 1,927 selected inputs and 413 imported-resource
files unchanged. Native executable and DLL hashes describe the captured
snapshot; the public audit does not require those binaries or assets. Toolchain
and Desktop state were outside that continuity check.

The public projection contains hashes and typed receipts. Private paths,
addresses, assets, screenshots, save payloads and original bytecode are absent.
The two earlier harness failures and the genuine live-owner-guard RED remain
separate historical failures. `packet.py --private-root <build-directory>` can
recheck the exact projection against those retained private reports. Its
optional `--cohort-log <log-file>` checks the measured CTest times.
The earlier four-profile PASS receipts and their captures, including the
100.70-second cohort, remain private historical evidence. A separate
intervening selection passed five of seven
tests: all three public regression cases passed, while two SDK profiles failed
during SDK setup, before terminal preparation. Its 131.58-second elapsed time is separate from the
current four-profile result; the clean-profile root cause remains unconfirmed.

A preceding SDK cohort passed three of four tests in 69.32 seconds. Its clean
profile recorded no right click in three 50-event input batches, despite source
focus and its process owning foreground. Setup then failed its Table-hit check
before terminal preparation. The typed history retains actual failed-process
artifacts and unchanged selected inputs/resources. The helper now waits for
actual serial events and lets ordinary SDK frames consume the pending batch.
That correction and the fresh passing cohort do not qualify unrestricted input
timing or extended play. Earlier 68.52-second passing captures remain separate
private historical evidence; these elapsed test times are not FPS measurements.

Run the Java-free public audit and corruption controls with:

```text
python tests/reference/client/workbench_open_shutdown/test_packet.py
```

This qualifies a native C ownership join after source stop. It does not supply
Minecraft.d, a source Container close, e=d, r=NULL, drops or a forced World save.
It makes no Java GC timing, original pixel, Linux SDK, global focus or FPS claim.
The disk comparison starts at the stopped selected saves tree; it does not cover
all process disk or promise persistence of unsaved cursor/grid state.
