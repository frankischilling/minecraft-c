# World brightness observations

The fixture contains 12 observations from unchanged original `fd.c(III)F`
in the pinned Beta 1.7.3 client. The observer allocates a genuine original
World with Object-only allocation and constructs a real `rh` Dimension. It
authors the final World.t field reflectively. These preparations do not run
the World constructor or bind the Dimension to a World.

The camera-independent coordinate X=32000000 makes original `fd.n(III)I`
return 15 through its actual outside-border branch. Ten authored raw float
values in the Dimension's actual float[16] array exercise the selected entry,
including negative zero, infinities and NaN bit patterns. Two cases observe
the original null Dimension and null float-array exceptions. They do not
qualify all possible NaN behavior, loaded Chunks or the complete light query.

The 16-byte original brightness body has SHA256
`393c67b2867ceac2579260ee9fc70759bc7e7790586855787262a4a24935558c`.
[Source pins](source-pins.json) retain the original class and method identities.
No original classes, assets or executable method bytes are redistributed.

To recapture with JDK17:

```text
python -B tests/reference/world/brightness/capture_reference.py \
  --client-jar /private/b1.7.3.jar --output /private/new-brightness-capture
```

The output directory must be fresh. The runner checks original input hashes
and JDK identity, pins the selected method bodies, and records bounded process
receipts. The observer denies network access, listeners, file writes and
native links. It requires no SDK metadata libraries or downloads.

The public `world.brightness` CTest requires successful native completion and
compares every [captured row](finite.json). Authored native controls separately
check null ordering, failure before the array load, caller output preservation,
unusual floating controls without arithmetic, client namespace admission, and
capture of the old table across real Registry resource callbacks. That callback
replaces the actual World.t field and drops its preceding native occurrence;
the query must keep the old provider/table alive through its final array read.
Native owners are genuine RAW Worlds, so World construction and complete
client ticking remain outside this fixture's scope.
