# Original compressed-NBT authored failure controls

Separate supplement to handler metadata output. Every selected call reaches unchanged original as.a(nu,OutputStream) and installed JDK17 GZIP/DOS methods. An authored real ByteArrayOutputStream-backed OutputStream commits each reached write to its actual byte store before optionally throwing java.io.IOException. Flush/close counters record reached calls; the helper catches the real thrown exception only outside the original source method and retains its class/message/suppressed list.

Nine cases: complete small tree; constructor header-write failure; serialization write failure with returning finally close; normal underlying close failure; serialization write failure plus failing finally close; normal finish-write failure; null underlying stream; flush failure plus successful close; flush failure plus failing close. The serialization cases use a genuine original byte-array tag of deterministic xorshift32 input to force deflate output before source serialization returns.

Freeze sources/scenarios/driver/tool/JAR pins before javac. Execute ordinary and independent read-only JDI processes with the same compiled helpers. The debugger reads fields, arguments, returns, exceptions and Code only; it performs no target invocation/allocation/writes. Verify as source22 versus30 and constructor prefixes, actual original exception/catch/rethrow locations, child closed/end fields, counters, committed byte prefixes, replacement and JDK suppression behavior. These authored stream failures are not observed original operating-system faults, native FOS behavior, World metadata transport, or whole-game startup.

The recorded cohort is Windows x64 Temurin17.0.17+10. Other host/JDK17 profiles must execute and retain their own observations. The driver pins actual original/JDK class and Code metadata, all installed-JDK native libraries, helper/tool inputs and unchanged compiled helper bytes. It records actual release, host, Python and complete captured streams.

The ordinary and read-only-JDI source outcomes, source22/30 prefixes, exception selection, suppression, exact underlying call counts and committed bytes must match within the recorded profile. The helper never resamples source failures into expected output or substitutes an encoder. The exact normal small NBT payload is independently decoded. A failed high-level GZIP write can leave a corrupt CRC in the later finally-finished bytes; failed outputs are retained and are not passed off as valid saves.

Exploratory failed audit attempts are retained privately: one initially expected zero underlying closes for the successful case; another omitted the incidental JDK File Code pin from its authority table. The corrected assertions retain the actual successful close and JDK native-library call. Neither failed audit is credited as qualified evidence.
