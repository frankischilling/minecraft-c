# Original client World paths

This package observes actual original FD path wrappers, genuine EW captured BlockAccess, FW search, D Points, LF heap, JX/WM map and DH paths from the unchanged Beta 1.7.3 client JAR. It executes original classes and queries, with ordinary and separately labelled read-only JDI observations. It does not replace a getter, BlockAccess implementation or virtual method.

```powershell
python tests/reference/world/path/capture_reference.py --client-jar b1.7.3.jar --output .local/world-path-original-20261031b
```

Use matching JDK 17 tools and a fresh ignored output directory. The driver admits exact JAR/class/method Code pins, runtime class origins/resources, original initialization closure, authored inputs and compiled helper classes. Every public text file is LF before capture. No original source implementations, binaries, assets or generated answer tables are public.

`profiles.tsv` declares 64 finite calls. `common-preparation.tsv`, `scene-preparation.tsv` and `component-preparation.tsv` declare the source operands, terrain and genuine component call sequences. Profile positions and target values are decimal; range/width/height are raw binary32 hex words. Components use original constructors and entered methods, including private FW leaves through reflection. They are component qualification, rather than an assertion that every FD wrapper executes that leaf.

The finite controls cover exact, straight, symmetric, detour, partial and null results; nullable source/target/bounds; zero/negative/NaN/infinite ranges and dimensions, including a negative EW rectangle; genuine open/closed Wood/Iron Door metadata; water/lava/material classification; one-step and drop1/2/3 versus the fourth clear drop; descent to Y0 versus initial Y0; EW block fallback versus unchecked metadata edges; lossy packed Point-key aliases; wrapping Point distance; LF ties, stale slots, duplicate insertion and growth above1024; JX growth at13 and clear, with actual old/new heap/map backing identities; and shared DH cursor/array identity, waypoint order and source null/index failures.

Private `observations.json` exposes:

- `finder_records`: actual JDI call-return states, retaining the original FD-local FW/EW receivers even when ordinary helper fields remain null.

Actual reference arrays retain their full length and every null/stale slot. Every D coordinate/key/index/cost/predecessor/closed field, JX bucket/WM chain and LF/neighbor/DH array remains observable. Traversal records aliases rather than flattening nonnull references. The `extra` Object[] root is an authored holder; it is not an invented original field or a native source-allocation claim.

A paired native observer may compare that declared result view separately, then compare its complete actual FW/EW graph against the JDI receiver view. This is finite path-body evidence over authored cached terrain. It does not establish arbitrary generation, combat, movement following, ownership failure timing or unrestricted client playability.
