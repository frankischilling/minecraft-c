# Original client Mob ticks

This package runs actual original constructors and virtual `w_()` calls for the eleven supported Mob kinds from the unchanged Beta 1.7.3 client JAR. It uses genuine World/provider/Chunk/Entity objects and original queries. It neither replaces classes or virtual methods nor represents Mobs as Players.

```powershell
python tests/reference/entity/mob_tick/capture_reference.py --client-jar b1.7.3.jar --output .local/mob-tick-original-20261031a
```

Use matching JDK 17 tools and a fresh ignored directory. The capture verifies the JAR inventory, whole-class/method Code pins, actual runtime origins/resources, class initialization closure and live reached Code. It runs ordinary and read-only JDI executions and preserves before/after input and compiled-helper fingerprints. Public text is LF; no original Java, binaries, assets or generated answers are exported.

## Two separate observation contexts

Every original constructor executes normally on the existing process profile. Its raw fields, bounds, watcher, private Random state and shared Math context are retained in `constructor_contexts` before preparation. JDI separately observes actual default-Random U/nano pairs and constructor RNG returns. Constructor entropy remains unnormalized and is not a claim of identical profiles between independent processes. The first Math holder initializes in its actual constructor context, not through a seed injection.

For active-body comparison, `common-preparation.tsv` declares fixed mutable operands. These include LS.F=.25, G=.015625, aj=.5, source pose `(8.5,64.5,8.5,30,0)`, previous angles0, actual Slime size setter e(2)/delay15, Chicken egg timer6000 and Squid phase increment .1. Own and World Random seeds are caller inputs applied before the observed call; no default profile is rebound. The raw constructor records remain separate and unchanged.

`profiles.tsv` lists 62 finite calls. `scenario-preparation.tsv` lists their exact additional field/setter/watcher/terrain/secondary-Entity operations. Both source and native fixtures consume these authored inputs; captured snapshots are observation data, not execution inputs. Ordinary Entity publication is original **FD.b(sn)**, which updates loaded-Entity and Chunk membership. FD.a(sn) is the weather-list overload and is not used for publication.

World seed23 and 25 actual cached normal Chunks at X/Z -2..2 provide a Stone plane at Y63 and genuine height64 arrays. Light arrays are authored dark values. Raw water/lava cells and eye-boundary blocks are explicit scene inputs; all access, material, collision, light and presence queries execute original bodies. No terrain-generation equivalence is claimed. Each call begins with the original pool reset helpers; no pool is reset during active execution or after failure to hide effects.

## Machine records and comparison rules

Private `observations.json` contains full `tick_records`, `prefix_records`, selected `comparison_records`, source phase order, constructor/default-entropy records, coverage and limits. Tick records have `before` and `after` maps with `fields`, `bounds`, `watcher`, seeded states, pool cursors, actual lists/cache and secondary entities. Field names include their declaring owner. Floats/doubles retain raw IEEE hex words. Strings retain content, including watcher17.

Reference values carry actual class plus observer identity; `reference_roles` maps known objects to actor/World/bounds/Random/watcher/secondary roles. Native comparison preserves aliases and never turns every nonnull object into one value. Absolute Entity ID (`sn.aD`) and shared-Math/default-constructor states remain distinct observation contexts; they are not rewritten in the source records. All other compared active fields derive from the authored preparation.

Events retain one ordinal and exact order. `SOUND` is case, ordinal, actual name, three binary64 position words and two binary32 volume/pitch words. `PARTICLE` has six binary64 words. `ADD` records actual class and three binary64 position words. Cell/range/remove events, when reached, remain explicit. Prefix events are read from the actual observer List at that suspended point.

This is finite body qualification, not unrestricted gameplay, a rendering proof or a generic success for all descendants. Actual path/combat/damage/drop behavior beyond a selected native boundary remains original-only evidence until its native body is implemented. Raw constructor and active Math entropy are preserved separately, and no JVM entropy is injected into a native application profile.
