# Original client named Entity factory

Two fresh Windows JDK17 processes, one `-Xint` and one default, called unchanged
`jc.a(String,fd)` ten times and then invoked original `sn.a(fd)` on the first
Pig. They did not enter AG rendering or CY ticking. The supplied NULL World is
the same operand used by AG at factory call48. This packet makes no native,
server, JDI, call-order, whole-frame or pixel parity claim.

The declared inputs cover unknown, NULL, empty and lowercase names, abstract
`Mob`, three Pig constructions, equal-valued distinct String input, and an
actual original World. All ten factory calls returned normally. The three Pigs
were separate WH objects with IDs0/1/2 and +1/+1 deltas. Their selected fields
were width/height0.9, health10, `/mob/pig.png`, and Byte watcher entries0/16 both0.
The two `Mob` calls returned NULL after genuine caught `InstantiationException`
stack traces. Other unknown names returned NULL silently.

Original `sn.a(fd)` rebound the same E0 receiver from NULL to the actual World.
Only that selected reference changed; the recorded World/list state and raw
receiver entropy stayed unchanged. The World came from an owned copy of an
earlier Furnace SDK save, loaded through actual FD/MX, RH/XA, OK and LM. It had
time211 and a saved Furnace at0,64,2. All thirteen source files remained exact;
only `alpha/session.lock` changed in each independent copy. No Player entity was
constructed from the serialized Player input.

`finite.json` retains both modes' actual structured observations, including all
five declared entropy fields (`ls.aj`, `ls.G`, `ls.F`, `sn.aS`, `sn.bs.seed`). They
differ between VMs and are omitted only from `stable_projection`. No fields,
Random seeds, maps or clocks were repaired. Original constructor stores and the
explicitly declared original World setter are source effects.

`NamedFactoryObservation.java` and `cases.json` are byte-identical to the executed
inputs. Portable runner, publisher, validator, controls, header and prose were
packaged after execution and were not used to run these two VMs. Archive
Class/Code hashes and loaded-resource identities are not a live-Code trace.
Registry snapshots are canonicalized observer output, not HashMap iteration
order evidence.

Raw stdout/stderr, private process receipts, classes, archives and save bytes
stay external. `receipts.json` records their complete byte counts and hashes;
`diagnostics.json` contains bounded parsed diagnostic fields. Published command
arrays are role projections, not verbatim private commands. The physical
publisher rechecks every selected input/product, exact command, source/copy
inventory, original archive and both complete raw streams before any write.


The source manifest binds the external save; its bytes are not distributed.
`native-observations.h` exposes only three finite Pig field projections and the
same-receiver World-reference transition. It excludes constructor entropy. The
original abstract-Mob NULL result requires caught-exception printing; a native
print52 frontier is not replay of that outcome. See
[the source note](../../../../docs/testing/named-entity-factory.md).
The derived header serializer follows the repository's clang-format18.1.3
layout; this publication formatting was applied after original execution.

`run_native.py --executable NATIVE_EXE --work-dir WORK_ROOT` runs the separately
built native fixture in fresh directories with the authored Mob-construction
resources. It preserves both bounded pipes, the child receipt and input
continuity. Its finite Pig/header comparison and additional native assertions
do not expand the original execution scope above. The fixed native fixture
constructs two Registries, so its transport gate requires exactly two ordered
`151 recipes` / `16 achievements` banner pairs before the terminal footer.
The 64 portable corruption controls include missing, extra and reordered
native banners. These authored transport inputs are not native executions.
