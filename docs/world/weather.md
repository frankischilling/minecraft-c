# World weather update

`mc_world_runtime_tick_weather` implements client `fd.m()V`, the weather call at bytecode 1 of `fd.l()V`. It runs on an actual CLIENT GAME World and its current WorldInfo, dimension provider and ordinary Random owners. It does not complete the aggregate World tick. Dedicated-server weather remains separate work.

The dimension provider's `e` field selects the no-sky return before the lightning counter, WorldInfo, Random or floating arithmetic is reached. Otherwise a positive World `m` decrements first. The thunder timer runs before the rain timer. A positive timer decrements and toggles its flag only when it reaches zero. A nonpositive timer draws a new duration from the actual World Random, with the source's different bounds and offsets for each flag. Captured setter receivers and subsequent owner reloads follow the bytecode order.

The previous rain value is stored in `i` before its flag read and arithmetic. The source widens the current binary32 strength, adds or subtracts the binary64 constant with bits `3f847ae147ae147b`, then narrows the result back to binary32. Using a binary32 `0.01f` step changes observable results. Ordered clamps preserve NaNs and clamp infinities. Only after rain is stored does `k` capture the previous thunder value and the thunder interpolation run. The implementation checks the native strict floating environment when each first conversion is reached, retaining all earlier timer, Random and field effects on failure.

The call borrows live, exclusive World and dependency owners through its return. It neither retires them nor supplies a synthetic provider, Random or WorldInfo. RAW and failed-construction source prefixes retain their actual phase; the weather operation can proceed until a reached missing receiver or native admission fails. Private WorldInfo field kernels cover the original scalar accessor bodies on those live prefixes. Existing public WorldInfo operations keep their READY admission and layout.

A successful call publishes a fresh empty diagnostic. An entered failed call retains the reached source PC and child status, and publishes that attempt to `World.last_error`. Rejected client-domain admission leaves previous World diagnostics intact. Native unsupported states are not fabricated Java exceptions.

The authored comparison uses unchanged client classes from the pinned b1.7.3 archive. Four completed Overworld constructors exercise every initial rain/thunder flag pair. The 64 weather observations cover timer reset/decrement/toggle paths, cached Gaussian Random state and continuation, repeated calls, signed zeros, subnormals, infinities, NaN payloads, two double-step witnesses and six interrupted nullable-owner prefixes. Native checks also cover strict-FP failure prefixes, real server-owner rejection, wrong-side WorldInfo, active-call admission, RAW WorldInfo field access and fresh retries. The unchanged public WorldInfo regression runs alongside the new weather test.

The no-sky comparison has a narrower construction scope: the original Nether World completes construction, while the native World retains its genuine unsupported generator-construction prefix at PC 403. Weather reaches the actual provider `e` return at PC 10 without using that missing generator. Those rows establish the weather method prefix, not completed native Nether construction. Neither provider admission nor construction status is changed.

The paired server method `dj.i()V` was inspected for the scalar field map and matching 395-byte control layout. No server weather execution, normal client loading sequence, scheduler, sky notification or whole World-tick result is claimed by this increment.
