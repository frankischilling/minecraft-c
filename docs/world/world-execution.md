# Nested World ownership and Entity activation

The native execution owner now keeps up to eight independently evaluated World
occurrences in stable slots. Each slot has its own precharged WorldAccess lease;
closing an unused outer slot cannot hide or move a failed inner slot. Alias
Worlds acquire separate actual bindings. The two existing inline loader copies
remain fixed storage. No Entity field or public error layout grows.

The caller retains the exact nullable World before later source arguments and
keeps the defining code and other argument owners alive. A successful child
releases its transient binding promptly. A failed child retains its actual
World and protected producer until checked native retirement. Tokens identify
owner, slot and generation; stale tokens preserve output on refusal. Native
cleanup clears expired typed views before releasing actual rights and never
replays a getter, callback or source body.

A new push refuses when the current scope already holds a concrete callback
failure or a copied loader diagnostic. Failed lease inspection also goes through
checked admission: valid IDLE is a no-op and an entered ARMED parent remains
eligible for genuine nested work. Malformed state refuses before changing site,
output, World binding or slot ownership. This preserves actual callback reentry
while preventing a new scope from bypassing a returned failure.
