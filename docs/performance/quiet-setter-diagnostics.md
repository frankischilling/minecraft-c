# Ordinary setter success diagnostics

The success-diagnostic change reduced scene-median elapsed time by 7.8% to 20.2% in eight warmed AIR no-op scenes. All 32 adjacent baseline/candidate pairs favored the candidate. These are complete quiet public setter calls plus their timed loop, with a nonnull mutation diagnostic. They establish no NULL-error, changed-cell, natural-population or gameplay FPS improvement.

The captured cohort passed an independent audit of all input fingerprints, raw timings, pair/order statistics and native semantic receipts. The [finite record](../../tests/benchmarks/quiet_setter_diagnostics_windows.json) retains all 64 process contexts, all 448 raw QPC samples, exact raw stdout receipts, invariants and cleanup footers, every adjacent pair, both run-order strata and extrema. It also records all 188 finite native semantic controls. Artifact locations use logical roles; input, object and stream fingerprints remain bound to their actual receipts.

## What changes on success

An ordinary World setter allocates and initializes a temporary mutation diagnostic before entering the shared body. Previously, a successful body reset that workspace to its canonical success value, then its ordinary wrapper copied the workspace into the caller's diagnostic. The candidate initializes the caller's diagnostic directly after successful completion. The returned status remains OK. The four Boolean APIs preserve the lower call's result, including false for these resident AIR no-ops; the metadata-only API has no Boolean output. A Blank Chunk can return true without changing its planes.

The first workspace allocation/initializer and allocation-failure behavior stay in place. Failure still projects the actual initialized frame, status, cause and reached prefix. The shared mutation body, acquisition, Chunk operation, callbacks, child ownership and cleanup remain the same. This is a change to native diagnostic projection, not a substituted World operation or rollback.

The three retained callsites explicitly select the existing frame reset: retained metadata mutation, owned block mutation and internal quiet mutation. Their raw/completed channels, parent-error projection choice and checked retirement continue to use the retained frame. This separation matters because an internal success can preserve an enclosing parent's diagnostic rather than replace it with a new success value.

The measured mutation diagnostic is 24,296 bytes. The experiment compares 22,646 bytes: 6,298 named and 16,348 unknown bytes, excluding only 1,650 bytes established as padding. The layout fingerprint is `8267465906294600077`. Representation size does not specify which byte-copy instructions a compiler removes.

## Fixed work and elapsed results

Each scene uses 8 or 256 sparse resident Chunks, provider mutation depth 0 or 1 opened explicitly by the fixture, and the ID-only or ID-plus-metadata quiet public setter. The target is existing AIR with zero metadata. Each call starts with `changed=true` and must return false. Every 32nd call adds 524,288 block units to X to exercise the existing packed-key alias. No complete population-neighbor square is prepared.

Each fresh process warms both setter bodies at every selected coordinate, then records seven samples of 8,192 calls. The QPC interval includes coordinate and alias selection, the sentinel store, complete setter calls, status/changed accumulation and checksum folding. Setup, warm-up, diagnostic/state comparisons and cleanup are outside the interval. It is elapsed time, not API-only cost or process CPU time.

The four rounds alternate adjacent pair order, giving each scene two baseline-first and two candidate-first pairs. A process result is the median of its seven samples. Each table value is then the median of four process medians for that variant; the percentage compares those two variant medians. All samples and pair results remain in the record.

## Finite native controls

The same genuine baseline/candidate World objects passed 188 native semantic controls before timing:

| Group | Fresh processes |
| --- | ---: |
| Ordinary changed/no-op/failure diagnostic cases | 102 |
| Blank Chunk cases | 30 |
| Retained calls and joined descendants | 36 |
| Cold no-ops, NULL provider and activation callback failure | 10 |
| Existing mutation, query, rail and client/server ring controls | 10 |

The retained cases exercise actual execution tokens and checked call/World/receipt lifetimes, genuine Torch Item publication, joined fluid quiet/set/remove calls, canonical returned diagnostics and selected preserved parent prefixes. The ordinary failure controls preserve actual reached diagnostics and untouched caller outputs. These are finite native controls; they do not establish complete state or original-program parity. In particular, the successful outer quiet-fluid case can reset the final error after its child returns, so it does not establish every intermediate quiet-child error byte independently.

Earlier preparations remain recorded as failures outside the passing 188 and the timed cohort. They exposed a missing initializer declaration, a cleanup drain after terminal retirement, a schedule radius outside the loaded ring, an unbound EntityClasses dependency and a missing Math execution required by retained insertion. Separate diagnostics identified the returned failures; later versions corrected the declared native inputs or cleanup and repeated qualification. No Source assertion was weakened and no quiet/Torch mode was discarded.

The `world.ordinary_projection` regression runs 51 fresh processes across all five ordinary setter APIs, changed/no-op/bounds cases and NULL or oppositely poisoned diagnostic outputs. It checks all five Chunk planes, callbacks, pending/light/scheduled state, Random state and checked cleanup. Its compiler-derived layout mask compares every UNKNOWN byte and excludes only proven padding, without importing Windows size or layout constants.

The integrated Release build passed all 1,271 local Windows CTests without skips. The new regression also passed with optimized Python. On Linux, Clang 18 with ASan, UBSan and leak detection passed mutation, query, rail, client/server ring and ordinary-projection controls; GCC 13 separately passed strict syntax checks for the World implementation and new C fixture. These platform checks qualify the formatted source; the timing observations above remain Windows-only.

## Reproducing one current scene

Use the existing optional public harness with `MC_BUILD_BENCHMARKS=ON` and `BUILD_TESTING=ON`:

```powershell
cmake -S . -B build-windows -DMC_BUILD_BENCHMARKS=ON -DBUILD_TESTING=ON
cmake --build build-windows --target mc_benchmark_quiet_setter_noop
python -B scripts/benchmarks/quiet_setter_noop.py --executable build-windows/mc_benchmark_quiet_setter_noop.exe --artifacts C:/bench/setter-diagnostics --chunks 256 --depth 1 --setter metadata
ctest --test-dir build-windows -R "tools[.]quiet_setter_noop" --output-on-failure
```

Adjust the executable location for the configured generator. Use a short writable artifact root. Choose chunks 8 or 256, depth 0 or 1 and setter `block` or `metadata`. The runner retains complete raw output and file/input continuity evidence, rejects failed native captures and never retries a failed process. The reader CTests are separate from the optional native timing process.

One invocation measures one current executable. It supplies neither revision-comparison evidence nor FPS evidence. Comparative work needs separately bound products, the same workload object and library tail, balanced run order and the complete finite protocol used for this record. A different ABI/layout must pass its own diagnostic contract; compiling the target alone does not qualify these Windows counts or fingerprints.
