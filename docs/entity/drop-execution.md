# Entity drops in a shared execution

The private entries in `src/entity/drop/execution_internal.h` run the same
numeric and Stack bodies as the existing Entity drop API. Their explicit
execution and defining code bundle connect reached World insertion to the
caller's actual Math and ownership state. A missing context refuses; it does
not select the legacy route.

The numeric body still allocates and constructs its Stack before entering the
Stack drop. Stack entry allocates the RAW Item, captures the nullable
constructor World at `sn.a(Stack,float):5`, evaluates the original coordinates
and enters the actual Item constructor at 24. This constructor uses the existing
Java Math Random profile and performs no MathHelper invocation. The checked
constructor scope closes after that actual constructor work. Pickup delay 10
is stored at 31.

Publication independently captures the actor's current World at 35, before
the Item argument at 38 and invocation at 39. It enters the existing complete
owned World insertion body. Its first reached `in` invocation is the World
floor operation at `fd.b:8`; a missing defining Math namespace therefore stops
after Item construction and pickup delay, before World/Chunk membership.
Ordinary World insertion false is discarded at 42 and the Item returns at 44.

## Separate outcomes

The continuation Boolean, raw Entity status, actual World insertion Boolean,
runtime ownership result and Math cause are independent observations. An
ordinary completed insertion false permits return. A Math-only or native-only
stop can leave raw status OK while refusing continuation. The caller must stop
on the Boolean and preserve the actual reached lower frame.

One heap drop call contains its stable insertion frame and private runtime
result. Forwarding that result to a caller copies values; it acquires no close
authority. The inspect entry exposes the actual pending child, its typed
acquisition/Chunk diagnostics and the two recorded World tokens. Source
callback failure transfers its real producer occurrence through the existing
owned insertion protocol. This route does not retain a receipt after return.

## Checked retirement

Each initial close records its actual token, drained-local proof and failed
operand before the checked pop. A refused OPEN close remains pending. A
consumed non-OK close is recorded as consumed and never repeated, including
after its slot is reused. Native retry preserves the original failed operand.

`mc_entity_drop_native_close` closes only the call's recorded tokens, publication
before constructor. Explicit pending acquisition or Chunk-close capsules must
first drain under their exact restored scope. The helper does not discover or
pop arbitrary descendants, replay Source work, initialize another Math owner
or promote the original false continuation to success. Checked drop retirement
refuses while its recorded tokens or continuations remain unresolved.

Published Items retain their actual World/Chunk membership through failure and
cleanup. Cleanup does not create another Item, repeat constructor entropy or
perform another publication. Typed diagnostic borrows expire before their
actual frame/owner is retired; copied diagnostics own none of those resources.

## Scope

The retained Mob death entry in `death_execution_internal.h` carries the same
explicit context into the actual Sheep, Skeleton, Squid, ordinary Living and
Creeper-tail drop calls. Any false child, including raw OK, leaves that current
drop on the victim and stops before a returned-drop count, loop advance, Stack
release or later status operation. Existing cleanup closes only that actual
drop's recorded tokens before retirement; unresolved child work refuses.

The two independent Living death World bindings and literal client World
status return retain their existing bodies. They do not acquire extra execution
scopes. No Container close is added to this method. Controls cover 36 seeded
profiles, twelve remote-World receivers, every publication in a four-Item
Skeleton death, a second Squid publication's native refusal and duplicate-work
admission. Earlier published Items and actual Random/ID progress survive cleanup.

The native controls cover missing/limited Math, successful publication,
ordinary absence, null World, source callback failure, protected capture
refusal, native close refusal/retry, input admission and World-scope capacity.
Legacy Entity drop and animal/Monster death controls exercise the shared bodies.

The retained Mob death join uses this same child for its actual drop loops.
Player Stack drops and inventory scatter are separate overrides. Cold
import/generation and foreign provider/Store graphs retain their explicit
external lifetime contract. These entries alone do not complete Arrow damage,
Player wake, delayed removal, original audiovisual comparison or FPS testing.
