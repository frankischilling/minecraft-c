# Saving and returning to the title

The selected World loader retains a source leave operation for the Pause
screen's Save and quit action. It calls the same source World save route as
ordinary World saving, with the actual nullable Loading owner. A successful
leave then constructs and displays a fresh title screen.

The [source order record](../../tests/reference/client/save_title/README.md)
maps the verified client bodies and their seventeen hash-only Code pins. It is
static evidence; the native UI fixture has a separate execution scope.

## Source state and ownership

The World-change prefix saves statistics, clears view Entity `i`, performs the
Loading and sound operations, and saves the previous World before clearing
World `f`. It clears Player `h` only on the later null-target branch. Metadata
still precedes Chunk writes and late SizeOnDisk growth. The source provider's
ordinary eligibility predicate also applies to forced saving.

The full-save progress join uses a private GAME-only owner/stage adapter so
the actual LoadingScreen callback does not borrow an unused mutable cache
descriptor. The same nullable LoadingScreen is retained and invoked at the
same source sites. The shared lifecycle, public/options export behavior,
failure children and terminal ownership remain unchanged. Actual public raw
borrows still permanently select generic cache validation. The
[save contract](../world/saving.md#source-progress-ownership) separates the
qualified component controls and current bounded client passes from pending
full broad qualification. The separate current seed777 Create World SDK run
passes 2,616 checks through initial save, leave and distinct-epoch reload, with
independent NBT readback and no passive guard/monitor timestamp changes.

RenderGlobal and particle World fields retain the previous World because the
null branch skips their replacement calls. The selected Load keeps its own
World, Player, input and Handler alive after the App fields have cleared.
Native terminal admission counts the remaining actual occurrences and the
traced `i16`, `f69` and `h355` stores. It never restores historical App fields
or uses renderer retirement as ordinary World replacement.

Each retained leave has a separate result from the original successful load.
A failed save preserves its reached source prefix, including a cleared view
Entity with the old World and Player still published. The failure blocks source
continuation and replay. Native cleanup can inspect and retire the retained
graph without finishing a serializer, closing source output or fabricating a
title return. Retained leave records have an explicit native bound of 32.
