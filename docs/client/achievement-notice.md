# Achievement notice construction and state

The client notice owns the reached `vu -> ub` constructor prefix and its Item
renderer's `bb -> bw -> fh(0) -> ko` graph. This is CPU construction and
notification state. Notice and Item drawing still return an explicit unfinished
dependency.

The Biped contains nine `ps` parts, 72 directly allocated Vec3 positions, 72
original `ib` vertices, 216 distinct UV-copy vertices and 54 `tz` quads. UV copies
share the original position identities. Mirrored parts reverse their quad arrays
after UV assignment. The shared application Entity namespace supplies the
actual nonpooled Vec3 factory. Model construction and retirement never reset or
clear the movement pool.

Each Item renderer constructs two distinct `cv` objects, one inherited from
`bw` and one declared by `bb`. All instance defaults and the reached `cv.a`
class initialization are represented. The one ordinary default Random runs
after the complete Biped and both RenderBlocks objects. Only then does `bb`
publish its Random, true flag and final shadow values .15f/.75f. No seed0
replacement or omitted constructor child is used.

Native allocation and source construction are separate. RAW owners have no
constructor effects. Failed construction keeps every completed publication and
retains unpublished native children until retirement. The per-Item ledger has a
1 MiB default; Vec3 uses its existing separate Entity ledger. These native
policies do not claim Java allocation sizes or OutOfMemoryError timing.

`vu.b(ny)` stores the achievement title, obtains its description, then samples
the real platform clock and stores now-2500, the achievement and true. A failed
description leaves the new title and previous later fields. `vu.a(ny)` first
translates/stores `achievement.get`, then stores the achievement's name, samples
the clock and stores the achievement and false. Null operands retain those
distinct prefixes. Long subtraction uses the existing wrapping helper.

The concrete `kh` callback is allocated in the common Registry arena and holds
the actual typed application identity. It reloads the application's current
Settings, its named inventory binding `r`, and that binding's current code.
The current `w` array is not read. The retained LWJGL key-name table and existing
String/null formatter supply the caption, including holes, index failures and
formatting failures. A null callback returns the stored description identity.
No generic successful callback substitutes for `kh`.

Formatted Strings have separate runtime ownership. A notice retains its current
formatted description and releases it only after a later successful `e` store
or retirement. A failed formatting call preserves the old owner. Direct callers
transfer or free `mc_client_description_result`; copying its owning pointer and
freeing both copies is invalid. Stored Registry Strings remain borrowed. Runtime
formatting admits 1 Mi UTF16 units and an 8 MiB per-call allocation ledger;
unsupported locales and exhausted policies fail explicitly. Repeated reminders
do not grow the permanent Registry arena.

The private application header contains the complete existing application
storage. Production and the CPU observer use the same definition and access
unit. The application owns its Entity namespace and renderer classes before
notice construction, including at the menu, and reuses that namespace when
opening a World. Notice borrows prevent premature Registry/class retirement.
Every model position hold is released before the class owner retires. Session
storage is unchanged.

Inventory-callback installation belongs after genuine StatsWriter construction
and publication at the normal startup site. The current menu initializer does
not invent that completed `Minecraft.I` step. The isolated body observer calls
installation on actual diagnostic owners; its original helper invokes the
genuine `kh` constructor and `ny.a(gt)` methods.

The reference layer compares 140 constructor records and 151 notification
records against unchanged supplied original classes. It checks float/double
bits, model fields, vertex/position aliases, mirrored order, two RenderBlocks
instances and default-Random construction/state defaults. Cases cover Settings
replacement, live key changes, null `w`, null client/Settings/binding failures,
key bounds, null achievement prefixes, completion and 1000 actual reminders.
Native controls exercise a default-Random failure after both RenderBlocks
objects, 16 allocation-prefix limits, movement-pool isolation, borrowed owner
guards and terminal cleanup.

Original execution currently qualifies Windows x86-64, the pinned client JAR,
JDK17 and pinned LWJGL2.9.0 libraries/lwjgl64.dll. The genuine concrete `kq`
constructor supplies the original notice/client for callback cases; its real
Timer-hack daemon is stopped and joined. No display or login request is made.
That constructor has additional Timer/progress/second-Biped, sound/texture and
thread effects outside the compared notice graph. A complete Minecraft
constructor/bootstrap, Player tick, animation, drawing, texture/font/icon
rendering, licensing watermark and pixels are not qualified here. Real clock
samples are checked independently within each process; clock values and default
Random entropy are not asserted equal between processes.
