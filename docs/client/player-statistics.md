# Player statistics and application ownership

The application constructs its actual water texture effect after the achievement
notice, then initializes statistics at the reached Minecraft constructor call.
The water constructor reads the real flowing-water Block before statistics
initialization. The resulting catalog messages are `16 achievements` followed
by `151 recipes`; a cold standalone statistics entry has a different, separately
qualified order. Texture animation and RenderEngine registration remain separate
unfinished operations.

A locally selected username is decoded from UTF-8 into an owned UTF-16 String.
The application creates a real Session and retains it through statistics-writer
construction. The writer uses the actual GameDirectory and Session; publication
of Minecraft.I follows successful construction, then installs the actual
inventory achievement-description object. Startup does not join the worker.
Native retirement joins outstanding workers before releasing Session classes,
Registry, resources or the application.

The Session accepts counted UTF-16 text. The current statistics filename profile
supports English ASCII usernames and reports other names at the reached
lowercasing dependency. This is an explicit remaining compatibility limit;
decoding a CLI username does not establish general filename/locale support.

Each outer Timer tick services the retained writer before GUI/input work,
corresponding to Minecraft.k's xi.d call at18. This selected connection does not
implement all other Minecraft.k descendants. Retirement is a native ownership
operation and does not invent a source save or service call.

## Dispatch from the same Player

`mc_local_player_add_statistic` executes actual dc.a(Statistic,int). Null
statistics return before any application access. Achievement parent checks use
presence rather than a positive-value test; the application, writer and notice
are reloaded at the original sites. An unseen achievement reaches the real
notice before its writer increment. Zero and negative amounts remain valid.
Errors preserve the actual dc site and complete writer/notice child diagnostics.

Travel distance, jumping, falling and damage now invoke that concrete bridge.
A successful fall statistic continues into the Living/base fall body. A fall
of 2.5 blocks completes with its 250 distance units; a nonnull passenger retains
the increment before the unfinished recursive callback. Damage retains its
increment before the unfinished Living hurt invocation at gs158. The code does
not report successful health damage or larger-fall completion at that boundary.

The native callsite regression constructs a genuine application, Session,
writer, World and LocalPlayer. It checks completed jump, distance, travel and
small-fall totals; the passenger and hurt continuations; and exact null-App and
null-writer failure prefixes with balanced owner holds. Its explicit worker join
is a finite test observation, separate from production startup.

## Evidence and limits

pins 37 complete class files and 703 method entries, compares 20 actual dc
projections and the actual water-constructor fields, and checks the original
array/store instruction pairs. The corrected water diagnostics have a retained
old-body failing regression and independent corrected-product verification.
The unchanged-original profile currently qualifies Windows x64 only. Native
Debug and Linux sanitizer qualification remain distinct from that profile.

The initial combined Windows Debug integration passes 25 selected cases, including
the real App callsite regression, original comparisons, nine startup runs and
three terrain-view captures. The final full source then passes 307 Windows tests and 286 tests each on
sanitized Clang/GCC, with no failures or skips. These checks establish their
finite operations, not an active Player/World tick or a playable session. Full tick composition,
Living hurt, Container close, Item pickup, Map tracking/terrain updates and
complete startup/render/audio behavior remain unfinished.
